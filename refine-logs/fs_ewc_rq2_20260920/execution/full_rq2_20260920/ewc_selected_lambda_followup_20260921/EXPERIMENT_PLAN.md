## 阶段一：先判断保护生效，再比较平均性能

“第二个任务平均效果”定义为**完成第二任务后，两任务平均准确率 A2=(a21+a22)/2**，不是只最大化新任务a22。

1. 首先等初始14点全部有合法终态、λ=0完整完成；如进入补充搜索，合并其已完成轮次的有效观测后再选择；数值发散只算边界观测，不进入候选。所有候选须有完整50轮、有限状态、相同父模型/raw Fisher/配对输入、实际评估与checkpoint收据。
2. **实现确实起效**：λ>0，离开初始参考后有正EWC损失和非零保护梯度，且实际更新中仅注入一次EWC项。仅有配置字段λ>0或损失非零，不足以说明保护效果好。

## 阶段一B：首轮无合格λ时继续扩大或细化搜索

执行规则见 [refinement_policy.json](refinement_policy.json)。这是已授权的条件后续任务，目前等待首轮结果，不表示补充作业已启动。

| 首轮或补充轮的观测 | 下一步搜索 |
|---|---|
| 高端至少三个正λ均稳定，保护仍弱，未超过新任务/平均性能代价限，且没有已知更高发散点 | 从当前最大λ向上取约×3.16、×10；本轮结束后再判断是否继续扩展 |
| 已有保持收益，但新任务损失过大或平均下降 | 在弱/强保护与代价阈值交界处加密，寻找两者兼顾的窗口 |
| 较高λ数值发散 | 在较低稳定点和最近的较高发散点之间细化，不继续盲目增大λ |
| 最小正λ已经过强 | 向更小的正λ探索，约÷3.16、÷10；不对λ=0取对数 |
| 没有清晰阈值交界 | 优先细化最接近合格标准的有限点两侧，允许非单调的性能曲线 |
| 保护梯度缺失或发生代码、数据、OOM、收据错误 | 先检查实现或执行故障，不能只增加λ，也不能把技术失败记成算法发散 |

局部区间[L,U]采用对数四等分，插入三个新点：

`λ = L×(U/L)^(1/4)、L×(U/L)^(1/2)、L×(U/L)^(3/4)`。

每轮最多选两个区间、最多新增6个λ，排除已测/已排队重复点。参数用稳定的数值身份记录；新点可能有小数，须使用独立补充轮wrapper，不能直接套用当前只支持整数命名的run_trial，也不能修改活动队列的冻结代码。每轮开始前记录观测来源SHA、加密区间、拟运行λ、原因与固定协议；每轮完成后把结果与初始14点合并判断。找到候选后按原选择规则锁λ*，不必机械跑满额外轮数。

全部补充点保持seed0、SGD→SGD、同一个Task0模型及同一份重算raw Fisher、相同新head和输入RNG、lr0.02、batch128、第二任务50轮；只改变λ。数值发散保留为边界观测，不填写正式准确率。使用所有合法完成的初始点和补充点进行选择，保留所有负结果。

不设“只补一轮就结束”的限制。相关区间仍有可分辨空间时继续细化；当U/L≤1.10或无法生成不重复的内部点时，不在该小区间无限插点，而转查其他未解决区间。操作范围为正λ 1e−6至1e9（上限沿用现有trainer支持范围）。若证据支持的区间均已细化、可行扩展也已穷尽或受数值稳定性阻断，仍没有合格点，则如实报告“在已测范围和分辨率内未找到”，λ*保持未定，四行复跑不放行；不能宣称所有λ均无效。

各轮独立保存计划、代码/配置指纹、结果与统一观测台账。补充批次也等待GPU0–6全部空闲，每900秒检查，最多6并发。当前14点队列保持原样；补充计划具备合法输入与支持非整数λ的入口、验收后再提交执行。
